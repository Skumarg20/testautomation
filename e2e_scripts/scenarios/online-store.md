## What the KB and code say the journey is

**Two store modes behind one menu.**
- Top-level menu "Online Store" goes to `/other/onlinestore` (`margerpdata/DatabaseJson/menumaster.json`, id 5467). A newer menu row "Online Order" under **Sale** goes to `/report/crm/E-Commerce/dashboard` (`margerpdata/Database/AlterMainDBData.xml:484`, parent 112725066 = "Sale"). This matches MBC-17953 / MB-39073 "Online store page move to under sale main menu" (`jira_vectordb.csv#MBC-17953`, `jira_vectordb.csv#d6154930`).
- `/other/onlinestore` (`onlineStoreDashboard`, `Modules/other.home.module.ts:52`) calls `POST MargMart/Get`. If a Marg Mart store exists (`StoreData[0].RowId>0 && vendorId>0`) it opens the dashboard in mode `onlinestore` (Marg Mart). If only an own Online Store exists (`OnlineStoreData[0].RowId>0`) it opens mode `OnlinestoreNotMart`. Otherwise it opens `other/createStore` (`Component/Online-Store/dashboard/onlineStoreDashboard.ts:69-87`; `codekb:MargBooks:screen#e79a0e79`).
- Marg Mart is the external e-commerce site at margmart.com that is "directly integrated with the user's Marg Books database"; customer "orders will directly come into Marg Books" (`careportal_enriched_v5.csv#q183749`, `#q183865`; `careportal_enriched_v5.csv#ab90667b`, `#9c896621`).

**Store registration (create store).**
- Route `/other/createStore` (`OnlineStoreComponent`, `Modules/other.home.module.ts:53`). It has two tabs, "Marg Mart" and "Online Store" (`Component/Online-Store/app-onlinestore.component.html:26,29`; `codekb:MargBooks:screen#70dc4e76`).
- Fields: Store Name, Email Address, Mobile No., Store Type (Retailer / Distributor / both), Business Type, GSTIN, State, Address, Working Hours (Whole Day / Day shifts) and Working Days (`careportal_enriched_v5.csv#q183749`, `careportal_enriched_v5.csv#d835cffd`; form `app-onlinestore.component.ts` createForm, prefilled from the selected company).
- Defaults: Store Type 2, Business Type "GRO", Whole Day 09:00-19:00, Monday-Saturday on and Sunday off (`app-onlinestore.component.ts` createForm, about lines 166-202).
- The Marg Mart path saves through `MargMart/Save` and opens `https://margmart.com/vendor/#/registration?...` in a new tab (`app-onlinestore.component.ts:323-324`). The KB flow then continues on margmart.com: theme, Auto Build, store QR code, an email to set the password, admin login (`careportal_enriched_v5.csv#q183749`, `careportal_enriched_v5.csv#ab90667b`). The website must then be activated in the Marg Mart admin (Profile Icon > Settings > 'Shipping Charges with Order Amount' > 'Website Activation' > Activate), otherwise it is shown "under maintenance" (`careportal_enriched_v5.csv#54294ca4`). That part is outside MargBooks.
- The own Online Store path is `RegestrationSubmitForOnlineStore`, which posts to `OnlineStore/SaveOnlineStore` (`app-onlinestore.component.ts:670-731`). The API answers "Online Store Created and Saved Successfully" (`margerpdal/OnlineStore.cs:429`; `codekb:MargBooks:api#d7fb4bfa`) and the UI shows "Store Created Successfully. Redirecting to dashboared..." (`app-onlinestore.component.ts:725`). The save hardcodes AcceptOnline 1, MinimumOrderAmt 0, orderlimit "2000" (`:698-699,713`).

The button opens `OnlineStoreSettingComponent` as a modal titled "Store Setting" (`UtililityComponent/DynamicForm/form.component.ts:3431-3432`; `Component/Master/OlineStoreSetting/online-store-setting.component.html` header; Jira MBC-2591 "Store setting not saving in control room", `jira_vectordb.csv#c1072e26`).

Order Amount, Delivery Charges (+%), Add Taxes to the final cart value and Custom Charges are commented out in both screens: "Option hide by ashutosh due to marg mart have no option yet" (`online-store-setting.component.html:18-149`; `onlineStore.ControlRoom.Config.html:3-118`). **Order dashboard.**
- Route `/report/crm/E-Commerce/dashboard` (`orderdashboard`, `Modules/report.module.ts:229`; `codekb:MargBooks:screen#534afce8`). The title is "{{dashboardType}} Dashboard", where dashboardType is "Online Store" in both store modes and "E-Commerce" otherwise (`order-dashboard.component.html:6`; `.ts:362-383`).
- The store card shows the logo, name, GSTIN, Vendor ID (Marg Mart only), a "Switch to MargMart" / "Switch to Online Store" button, edit store, copy link, QR (Online Store only), and the tiles Order Limit, Valid Upto, Manage Item (count) and the order count (`order-dashboard.component.html:241-460, 461-690`).
- Grid columns: Order Date, Customer Name, Order No., Status, Qty, Amount, Action (view), Vendor, "Convert To Order" (`order-dashboard.component.ts:422-462`).
- Filters: Order Status (All / Pending / Converted / Order Rejected) and Vendor Type (All / Shopify / Amazon / Flipkart) (`order-dashboard.component.html:704-731`; `.ts:1461-1466`). Pending means every status except "Order Rejected" and "Converted" (`.ts:1446-1447`). Grids open on Pending (`.ts:1002,1587`).
- Marg Mart statuses: Pending 1, Payment Failed 2, Order Accepted 3, Order Rejected 4, Converted 5, Self Delivery 6, Delivered 7 (`order-dashboard.component.ts:293-300`). Accepting or rejecting goes through margmart.com `order/order-accept-reject-by-vendor` and shows "Status Updated" (`.ts:1007-1017`).
- Banner "Have bulk orders to convert in ong go? Import Orders in Bulk→", linking to a hard-coded `https://books5.margbooks.com/setup/transactionimport` (`order-dashboard.component.html:734-740`).

**Order → sale bill conversion.**
- KB: first approve the order in the Marg Mart admin (Sales > Pending Orders > Approved). Then in MargBooks go to "Online Store", select the order, click "Convert"; it opens as a Sale Bill; click Save (`careportal_enriched_v5.csv#q184057`, `careportal_enriched_v5.csv#1fe9aa64`; manual bank `Marg_Books_Test_Cases_v1.0.xlsx#MMT-025`, `#CRM-003`).
- Code: Convert To Order → `statedetails` → `ConvertToBill`. It picks the fixed ledger 80 (Marg Mart) or 83 (Online Store); if missing it shows "Transaction data not found !" (`order-dashboard.component.ts:640-643, 755-782`). Unmapped Marg Mart items ask "Items not mapped , Do you want to map now ?" and lead to `/report/crm/E-Commerce/itemMapping` (`.ts:1119-1124`). It then routes to `/transaction` with `dataNavigate.onlineStore=true` (`.ts:891-914`).
- On a first save of that bill (not temp-save, not resave), `InsertMargMartBill` and `ChangeStatusAndConversion` run (`Component/Transaction/InverntoryTransaction/processout.transaction.component.ts:11986-11988`). The second calls `OnlineStore/StatusUpdationOfOnlineStore`, which runs `update OnlineStoreOrder set orderstatus='Converted', convertedBillLinkid=… where linkid=…` (`margerpdal/OnlineStore.cs:559-576`; `codekb:MargBooks:code#58b3d1dd`). Marg Mart conversions are also recorded in `MargMartConvertedOrderDetails` (`codekb:MargBooks:schema#c3584eef`). On failure the UI shows "Issue while updating Status in Online Store" (`processout.transaction.component.ts:22088-22106`).

**APIs (route prefix `v4.2/[controller]`, `MargBooks.Middlewares/MargBaseController.cs:22`).**

- **Order seeding.** `POST OnlineStore/SubmitOrder` (`OnlineStoreController.cs:101-120`) inserts an `OnlineStoreOrder` row plus items for the caller's company (complinkid comes from the auth headers). Body: `storeorderid, orderdate, customername, customeremail, customermobile, totalamount, paymentmethod, orderstatus, shippingaddress, billingaddress, Items[{productid, productname, quantity, priceperunit}]` (`margerpmodel/OnlineStoreNew.cs:141-190`; `margerpdal/OnlineStore.cs:238-301`). It returns status "200" / "Order and items saved successfully." It validates nothing: no store check, no accept flag, no minimum amount, free-text status.
  - This seeds orders for the **own Online Store** mode only. The base URL of the OnlineStoreAPI service in QA is UNVERIFIED (`Global.whatsupaiwati.*`, `Globals/global.ts:1084-1092`, resolve against the environment's API base).

## KB vs live app (for a human to decide; not resolved here)
1. **Store settings documented vs hidden.** The brief (and the model) list acceptOnlineOrder, addTaxesFinalCart, DeliveryCharge(+%), CustomCharges and SetMinimumOrderAmount. Only Rate Selection is rendered; the rest is commented out "due to marg mart have no option yet" and there is no Save button. Support tickets MB-34343 and MBC-2591 complain about exactly this. Is the journey's "setting" half only Rate Selection?
2. **Minimum order / accept-orders are not enforced anywhere.** (The KB places shipping charges and website activation in the Marg Mart admin, Profile Icon > Settings > 'Shipping Charges with Order Amount', `careportal_enriched_v5.csv#54294ca4`.) Not in `SubmitOrder` and not in the dashboard (the filter is commented out). Create-store also hardcodes MinimumOrderAmt 0 and AcceptOnline 1. The care-portal article does not mention these settings at all; Marg Mart shipping charges live in the Marg Mart admin ("Shipping Charges with Order Amount", `Marg_Books_Test_Cases_v1.0.xlsx#MMT-018`, `#MMT-029`).
3. **Unreachable Store Setting modal** (`storesetting.component.ts`) on the create-store page: `StoreSetting()` has no caller in the template. **KB contradiction:** the L&D deck "How To Create Free Online Store In Marg Books" shows a "Store Settings" dialog over an "Update Store" window and an "Update Item Availability" dialog (`onedrive_processed_data.csv#f7587c14`, `#1690c328`), and the MB_Online_Store doc shows a "Create Online Store" button and "Open Orders / Manage Items/Orders / Store Reports" tiles (`onedrive_processed_data.csv#72932bc0`, `#a31a257f`). These screenshots are from the Marg ERP desktop app or an older web UI. Expected values (OS-12, OS-13) are unchanged.
4. **Store link and QR point at `http://localhost:4200`** in own Online Store mode. They also send complinkid/dbinfolinkid (base64) to the third-party `api.qrserver.com`. Looks like unfinished dev code (comment "Later to save in onlinestoreorder"). Possible security finding.
5. **Vendor Type defaults to "Shopify"** but `GetSavedOrders` returns no `vendortype`, so seeded orders may be invisible by default (OS-16).
6. **Hard-coded values in conversion.** State "Uttar Pradesh" and City "Delhi" are hard-coded on own-store orders (`order-dashboard.component.ts:1568-1569`), and the bulk import link is fixed to `books5.margbooks.com` (`order-dashboard.component.html:737`). Either can produce a wrong tax type or a wrong host on other environments.
7. **Create-store success check uses assignment** (`res.status = "200"`), so failures report success (OS-06).
8. **Status update has no tenant filter** and uses concatenated SQL (`OnlineStore.cs:570`) (OS-29).
9. **KB describes the Marg Mart flow; the code has a second mode.** The KB flow is approve in the Marg Mart admin, then Convert in MargBooks, then Save (`#q184057`, `careportal_enriched_v5.csv#1fe9aa64`). Note the label: the care portal says "Convert", the code's grid column is "Convert To Order". The code also has an own "Online Store" mode (`OnlinestoreNotMart`, fixed ledger 83, `OnlineStore/*` API) that the KB does not describe at all. Which mode does J37 cover? This pack assumes the own-store mode for automation, because only it can be seeded.
10. **Menu move in progress.** Sale > "Online Order" (MBC-17953 To Do, `jira_vectordb.csv#d6154930`) and a new UI (MBC-17208 LIVE TESTING, `jira_vectordb.csv#19d0a0e9`). The live menu location and selectors may differ from code on `main`.
11. **Rate mapping type.** (Related KB complaint: inclusive/exclusive calculation not working on upload, `jira_vectordb.csv#6d760c72`.) `getInventoryRate` switches on strings ("3", "5", …) while the model default is the number 5. A numeric value from the server would always fall to `ratea`, so M.R.P would upload at Rate A. Verify live with OS-11.
